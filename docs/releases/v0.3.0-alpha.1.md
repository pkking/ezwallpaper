# ezwallpaper v0.3.0-alpha.1 — M1 Integration Preview

**Preview / prerelease. Source-only GitHub Release.** This is the first tagged integration checkpoint after [v0.2.0](https://github.com/pkking/ezwallpaper/releases/tag/v0.2.0), not a stable niri/Noctalia desktop distribution, and not completion of [Epic #60](https://github.com/pkking/ezwallpaper/issues/60).

## What is included

- Headless `ezwallpaper-core` library and cross-platform `ezwallpaper` CLI for local assets and opt-in Bing, Pexels and Wallhaven SFW acquisition. Provider quotas, live remote availability and returned image dimensions are not proven by offline CI.
- Explicit asset inspection, decoded probing/derivation, local catalog and opt-in owned content store, with bounded source inputs and per-output orientation-aware pool selection.
- Persistent, per-output hourly rotation planning with independently chosen content IDs, same-hour idempotence, failure rollback and an example user-owned systemd timer. The 24-hour scenario is verified with a simulated clock; **two real elapsed UTC hours have not been observed**.
- Opt-in **Noctalia v5.2.1** IPC backend on Wayland, so Noctalia can retain wallpaper-renderer ownership instead of silently launching another swaybg process.
- Virtual **experimental niri** native compositor verification: real `ezwallpaper rotate next --apply` through Noctalia IPC, dual-output SHA/state and independent pixels, same-bucket duplicate handling and virtual disconnect/reconnect recovery. [PR #308](https://github.com/pkking/ezwallpaper/pull/308), [CI 43460114052](https://github.com/pkking/ezwallpaper/actions/runs/43460114052) (10/10 SUCCESS), [native artifacts](https://github.com/pkking/ezwallpaper/actions/runs/43460114052/artifacts/14055179035). The native niri source is **unmerged experimental PR #3800 at its pinned test revision**: this is not evidence for a released niri build.
- Opt-in user-run, reversible two-output screenshot verifier with a strict G-02 **4K landscape + portrait mode preflight**, and a *read-only* actual-hour/Noctalia/systemd evidence collector. Both have offline tests; no real user hardware was exercised by CI.

## Install from source

This GitHub prerelease intentionally provides **GitHub-generated source archives only**: no prebuilt Linux/Windows/macOS installers, no signed binaries, no system service, no crates.io publication. A current Rust/Cargo toolchain and the build dependencies for your platform are required.

```sh
git clone --depth 1 --branch v0.3.0-alpha.1 https://github.com/pkking/ezwallpaper.git
cd ezwallpaper
cargo install --path .
ezwallpaper --version
ezwallpaper doctor
```

For a local wallpaper, perform your own explicit opt-in after confirming the correct desktop integration:

```sh
ezwallpaper --setter noctalia doctor  # only in an existing Noctalia v5 session
ezwallpaper --setter noctalia --output DP-1 apply /absolute/path/to/wallpaper.png
```

Read [README](https://github.com/pkking/ezwallpaper/blob/master/README.md) for CLI options, and the [desktop evidence and rollback protocol](https://github.com/pkking/ezwallpaper/blob/master/docs/agents/desktop-integration-evidence.md) before attempting a real compositor/session test. Nothing in this release auto-enables wallpaper timers or edits root-owned greeter/boot files. Check for competing wallpaper owners before enabling periodic rotation.

## Verified scope and known limitations

| Capability | Verified | Not yet verified |
| --- | --- | --- |
| Core/CLI | CI Rust tests and offline CLI smoke on Linux; portable Windows/macOS test jobs | Real Windows/macOS/GNOME/Plasma desktop wallpaper pixels across OS versions |
| Noctalia + niri | Actual native IPC, both **virtual** rendered outputs and recovery on pinned experimental niri PR #3800 + Noctalia v5.2.1 | Released niri, production physical monitor/driver/GPU combinations |
| Two-output rotation | Actual native rotation controller in one UTC hour, persisted state, both virtual framebuffer pixels; simulated 24-hour controller tests | Two adjacent **real** UTC hours with systemd user timer, session re-login and timer causality |
| Mixed-DPI G-02 | Exact **3840×2160 / 1.5 + portrait 1080×1920 / 1.0** mode preflight and safe opt-in restore tooling | Physical GPU, actual 4K + portrait panels, unplug/replug and lockscreen |
| SDDM / Plymouth / video | Versioned event and reversible staging contracts | Real login theme, Plymouth/initramfs runtime outcome, continuous animation, PAM/lockscreen and widgets |
| External services | Stub/offline provider tests and bounded requests | Provider live quota behavior; accurate Noctalia weather or executing-agent count |

**Acceptance boundaries:** A green native virtual pixel test is `VIRTUAL_VERIFIED`, not `PHYSICAL_VERIFIED`. A successful `--force` rotation in the same hour does not establish hourly scheduling. Matching wallpaper IPC paths do not establish physical pixels; matching virtual display geometry does not establish monitor provenance. Those [Epic #60](https://github.com/pkking/ezwallpaper/issues/60) acceptance gates remain open.

## Release engineering

- Both Cargo workspace packages declare `0.3.0-alpha.1`; the CLI's local Core dependency also declares a matching registry version for eventual publishing.
- The release workflow checks package metadata and Core crate dry-run packaging in a read-only job, and only creates this prerelease from an **exact successful master CI release commit**. The write token belongs to the GitHub-release-only job. No crates.io upload is performed.
- No tracked Cargo.lock is included in the source archive; dependency resolution may differ over time. Verify runtime/compiler compatibility for your host rather than treating this as a reproducible, signed binary distribution.
- To publish to crates.io in the future, publish the matching Core prerelease **before** the CLI prerelease, then validate the CLI's registry dry-run; this M1 deliberately stops at GitHub source distribution.
