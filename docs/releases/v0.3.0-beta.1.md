# ezwallpaper v0.3.0-beta.1 — M2 Physical Desktop Beta

**Source-only GitHub Beta prerelease candidate; not stable.** Actual publication status is recorded only in [GitHub Releases](https://github.com/pkking/ezwallpaper/releases). Tested evidence below primarily comes from [the published Alpha](https://github.com/pkking/ezwallpaper/releases/tag/v0.3.0-alpha.1) executable at commit `4e72605fe788f1c1da1cb9aeba103353df547838`; the candidate version must still pass final-head CI and clean-install qualification. No installer, signed executable or crates.io publication is included.

## Included capabilities

Headless asset Core and portable CLI; local asset pools and opt-in Bing/Pexels/Wallhaven access; per-output stateful rotation, stable content IDs, single-epoch idempotence, Noctalia v5 native IPC, output-specific wallpaper getter and reversible opt-in desktop verification. Timers remain user-owned and opt-in.

## Source installation (once the prerelease actually exists)

Requires Rust/Cargo and platform system dependencies. Nothing enables systemd timers, downloads images, or changes your desktop automatically.

```sh
git clone --depth 1 --branch v0.3.0-beta.1 https://github.com/pkking/ezwallpaper.git
cd ezwallpaper
cargo install --path .
ezwallpaper --version
ezwallpaper doctor
```

To test a local image, **only with operator consent** and in an existing Noctalia v5 session:

```sh
ezwallpaper --setter noctalia doctor
ezwallpaper --setter noctalia --output DP-1 apply /absolute/path/to/wallpaper.png
```

Use [desktop verification and restoration instructions](https://github.com/pkking/ezwallpaper/blob/master/docs/agents/desktop-integration-evidence.md) for profile-based rotation. Ensure Noctalia is the sole wallpaper renderer and only one timer drives the given outputs. Do not run `--force` as an unattended retry. Treat missing output, offline pool exhaustion and getter failure distinctly from successful replacement.

## Rollback / compatibility

Previous Alpha is retained at [v0.3.0-alpha.1](https://github.com/pkking/ezwallpaper/releases/tag/v0.3.0-alpha.1). Preserve the existing local image pools, profile and JSON-v1 state before upgrading. Test the Beta in a side-by-side, separately installed executable path and keep the previous executable for rollback; no migration or automatic system timer reconfiguration is performed by source installation. An isolated [#319 install/rollback check](https://github.com/pkking/ezwallpaper/issues/319) verified Alpha and older 0.2.1 writer compatibility on state *clones*; it is **not proof of Beta rollback**. Switch the existing user-owned service to the previous executable only after validating its state compatibility and restoring your original service configuration; never overwrite production state as part of a test.
