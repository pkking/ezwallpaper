## Scope

Proposed **source-only Linux/niri + Noctalia wallpaper release**. CLI/Core version `0.3.0`; local pools, optional providers, real hourly dual-output rotation with persistent schema-v1 state and opt-in user-systemd timer. The program does not install timers or mutate desktop settings automatically. No signed executable, crates.io publication, or OS installer is planned.

## Reliability evidence and residual risk (approved method, not release PASS)

[#325](https://github.com/pkking/ezwallpaper/issues/325) now uses a maintainer-approved **layered** acceptance method: L1 real scheduled online hours across observation windows and a verified reboot; L2 [#330](https://github.com/pkking/ezwallpaper/pull/330) 25-bucket simulated CLI subprocess state/ACK/crash test; L3 short real released niri/Noctalia physical dual-output IPC/pixels; L4 [#327](https://github.com/pkking/ezwallpaper/issues/327) real Noctalia recovery or explicit maintenance-approved support restriction. These evidence tiers are **not additive uptime**. The L1 summary has 43 genuine online buckets, all reporting successful core rotation, but 11 are journal-only and private raw artifacts are retained for authorized audit. Three hours had `SDDM SyncError: image frame probe failed` during a non-Stable SDDM integration side effect; primary dual-output rotation completed, and SDDM greeter/cache synchronization is **outside** this Stable support scope.

**Continuous 24-hour uptime/soak: NOT TESTED.** Long-running user-manager timer delivery, day-boundary/session effects, Noctalia degradation and other GPU/display configurations remain potential risks. Powered-off hours are never counted as successful online triggers. The physical cable hotplug (HPD) and unattended rotation while a display is disconnected are unverified and excluded from supported claims. Candidate real-hour functionality and Noctalia restart recovery observed; **visual pixel acceptance NOT PASSED** pending unobstructed retest. #326 candidate lifecycle and remaining #327 unsupported/untested scenario decisions are pending.

## Installation and removal (once a stable tag is published)

```sh
git clone --depth 1 --branch v0.3.0 https://github.com/pkking/ezwallpaper.git
cd ezwallpaper
cargo install --path .
ezwallpaper --version
ezwallpaper doctor
```

Source-only removal and retention instructions are in [README](https://github.com/pkking/ezwallpaper/blob/master/README.md#uninstall-source-only-installs). For production installs verify the target executable and explicitly inspect/disable user-owned timers before deleting binaries. Preserve profiles, pools, state and events by default. Roll back using a separately preserved executable and proven state clone; exact Beta/stable compatibility evidence remains part of [#326](https://github.com/pkking/ezwallpaper/issues/326).
