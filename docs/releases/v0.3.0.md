## Scope

Proposed **source-only Linux/niri + Noctalia wallpaper release**. CLI/Core version `0.3.0`; local pools, optional providers, real hourly dual-output rotation with persistent schema-v1 state and opt-in user-systemd timer. The program does not install timers or mutate desktop settings automatically. No signed executable, crates.io publication, or OS installer is planned.

## Reliability evidence and residual risk

[#325](https://github.com/pkking/ezwallpaper/issues/325) uses the maintainer-approved layered acceptance method: L1 real scheduled online hours across windows and a verified reboot; L2 [#330](https://github.com/pkking/ezwallpaper/pull/330) 25-bucket simulated CLI subprocess/state/ACK/crash test; L3 short real released niri/Noctalia physical dual-output IPC/pixels; L4 [#327](https://github.com/pkking/ezwallpaper/issues/327) real Noctalia recovery and support boundary. These tiers are not additive uptime. The L1 report includes 11 journal-only records; private raw artifacts remain access-restricted. Three SDDM cache-sync errors were a non-Stable external-consumer side effect; SDDM greeter/cache synchronization is outside this Stable support scope.

**Continuous 24-hour uptime/soak: NOT TESTED.** It is not an additional mandatory gate under approved #325 layered qualification. Do not claim multi-day timer/Noctalia endurance. Long-running user-manager delivery, day-boundary/session effects and other hardware remain risks. Powered-off hours are not successful online triggers.

### Explicit scope boundaries

The supported claim is limited to the tested connected dual-output Linux/niri + Noctalia environment and the specific behaviors above. Physical HPD is **UNSUPPORTED**. A naturally occurring in-rotation IPC timeout and a natural hourly rotation while an output is absent are **UNASSESSED**; automatic compensation/catch-up is not guaranteed. Long-term Noctalia health is an external dependency and is not promised. Multi-day soak is not tested and is not an additional gate under the approved #325 layered qualification. These dispositions are already approved scope, not pending risk approval. Evidence and classifications do not themselves authorize merge or release; exact-SHA STABLE_GO and separate maintainer merge/release authorization remain pending under #319. Future exact-master CI is a post-merge/release gate, not an impossible pre-merge CI requirement.

## Installation and removal (once a stable tag is published)

```sh
git clone --depth 1 --branch v0.3.0 https://github.com/pkking/ezwallpaper.git
cd ezwallpaper
cargo install --path .
ezwallpaper --version
ezwallpaper doctor
```

Source-only removal and retention instructions are in [README](https://github.com/pkking/ezwallpaper/blob/master/README.md#uninstall-source-only-installs). For production installs verify the target executable and explicitly inspect/disable user-owned timers before deleting binaries. Preserve profiles, pools, state and events by default. Roll back using a separately preserved executable and proven state clone; see [#326](https://github.com/pkking/ezwallpaper/issues/326).
