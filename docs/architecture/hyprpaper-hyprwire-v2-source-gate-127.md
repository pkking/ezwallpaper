# Hyprpaper v0.8.4 / Hyprwire v2: source-backed readback gate (#127)

**Result: CONDITIONAL / NOT READY for a production rotation adapter.** Released code provides strict named-output apply and a new-status-object path snapshot, but **not** a demonstrated long-lived stream of events for IPC-triggered wallpaper changes. A Hyprwire client implementation, version handshake, post-apply ordering and actual native compositor verification are still required. The correct next experiment is an isolated client-side **fresh status object created after apply**, not a direct conversion of `apply.success` into `PathObserved`.

This is a **release-specific reassessment** of [2026-10-28 upstream selection](backend-upstream-selection-83.md). Fixed GitHub release: [v0.8.4](https://github.com/hyprwm/hyprpaper/releases/tag/v0.8.4), released 2026-04-29, Git commit [`20fc0fa6c2056c388a4cd69cb394a9f989dd27c0`](https://github.com/hyprwm/hyprpaper/commit/20fc0fa6c2056c388a4cd69cb394a9f989dd27c0), `VERSION=0.8.4`. Do not infer different Hyprpaper versions are compatible; no binary or real desktop was run.

## Verification tasks before enabling a third rotation adapter

1. **Client/version pairing**: released [Hyprwire v0.3.1 @ `3e6865ce`](https://github.com/hyprwm/hyprwire/tree/3e6865ce5fd9237b58f5b2ce5de18814df3baff5) source proves a working C++ `IClientSocket` + generated client API and binary Hello/handshake/spec/bind/roundtrip pattern. **Still verify** the exact Hyprwire build used by the hyprpaper v0.8.4 package, generated hyprpaper-specific client headers, version-2 negotiation and whether an independently maintained Rust/CLI bridge exists. No new runtime dependency is authorized here.
2. **Ordering**: in isolated Hyprland/hyprpaper v0.8.4, enumerate names from manager events; create a status snapshot before apply; perform one explicit named path apply, receive its `success`; **bind a new status object**, verify subsequent `active_wallpaper(monitor,path)` with exact canonical path. Test old-path first, duplicate same path, wrong output, errors, timeout and exit.
3. **Real pixels**: inspect independent compositor screenshot for each monitor and verify second output unchanged. State should advance only with confirmed exact path readback; do **not** label path-level readback `PixelVerified` in product.
4. **Ownership**: confirm Hyprland session/socket already exists; no startup/kill, no wildcard monitor, no second timer and no automatic fallback, preserving Noctalia as default.

**Gate:** Hyprpaper remains **NOT IMPLEMENTED** in `src/backend/registry.rs` until actual compatible client source + bounded ordering tests + native compositor evidence justify a separate PR/decision. The existing wpaperd Decision A and Noctalia default are unchanged. This document creates no new supported desktop claim or new package dependency.

## Evidence limitations

Pinned hyprpaper release code establishes server-side calls/XML. Separate pinned Hyprwire v0.3.1 code now establishes the C++ client handshake/roundtrip pattern, but its precise compatibility with hyprpaper's **packaged** library, generated hyprpaper client bindings, event ordering after apply, actual Hyprland compositor pixels, hotplug and real session stability are unverified. **UNASSESSED**, not negative proof of impossibility. User desktop remains untouched; no test-owned compositor was started for this research document.
