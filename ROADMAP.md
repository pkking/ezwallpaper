# ezwallpaper — Product and Release Roadmap

**Scope:** from the existing cross-platform wallpaper Core/CLI to reliable dual-monitor niri + Noctalia usage, then unified desktop, lockscreen, login and boot backgrounds. This roadmap specifies *release acceptance*, not a release calendar or a count of Pull Requests.

**Last reviewed:** 2026-11-21 (post-Stable publication). Release status and proof can change: check the actual [GitHub Releases](https://github.com/pkking/ezwallpaper/releases), [Epic #60](https://github.com/pkking/ezwallpaper/issues/60) and [versioned goal-gate matrix](docs/agents/goal-gates.md). A merged PR or successful unit/CI test does not itself mean a real physical user scenario passed.

These are release **quality gates**, not automatically scheduled deadlines. The maintainers can narrow or broaden scope only through a documented Issue/ADR and an updated acceptance matrix. **M3 is intentionally narrower than M4:** a usable wallpaper application does not need to promise hourly Plymouth/initramfs rebuilds or a full lockscreen widget suite.

**M2 evidence boundary (2026-11-15):** G-01's 24-hour observation window included 15 successful online hourly triggers and 10 missed *while system powered off*; therefore it is **not 24 hours of continuous running**. G-02's 0.9594 / 0.9729 pixel matching used an unobstructed desktop with a static active color scheme; wallpaper-driven Noctalia dynamic palette remains outside that pixel assertion. A software-simulated `output off` does **not** establish physical HPD. These are scoped Beta results, not a blanket niri/platform guarantee.

**M3 reliability decision (2026-11-18, [#325](https://github.com/pkking/ezwallpaper/issues/325)):** Maintainer approved Option C. The oneshot CLI has no 24-hour process lifetime; longer-lived dependencies include user manager/timer, compositor, Noctalia and IPC. Acceptance uses L1 real online UTC buckets with independently attributed downtime, L2 [#330](https://github.com/pkking/ezwallpaper/pull/330) deterministic 25-bucket multi-process state/ACK/crash test, L3 real short-session dual-output getter/pixels with final-version change-impact review, and L4 [#327](https://github.com/pkking/ezwallpaper/issues/327) real Noctalia recovery or explicit risk-approved support restriction. The [L1 consolidated audit](https://github.com/pkking/ezwallpaper/issues/325#issuecomment-6981953714) records 43 genuine online natural-hour buckets across five completed observation spans and four reboot recoveries, with 53 offline buckets separately attributed: **full 22 / partial 10 / journal-only 11**. Published summaries support L1 PASS at graded evidence fidelity; direct IPC trace is unavailable for some buckets. Three SDDM cache-sync side-effect errors were recorded; core rotation continued successfully. [实机 L3/L4 证据](https://github.com/pkking/ezwallpaper/issues/325#issuecomment-6984080678): stable candidate `v0.3.0` at `7af165a7` passed true 16:00 UTC user-systemd dual-display getter/state/content-ID functional regression; pixels NOT PASSED at original thresholds. Simulated buckets and offline hours cannot be counted as live uptime. **Uninterrupted 24h Soak NOT TESTED**, long-running dependency risks disclosed; those dated checkpoints were later accepted for the bounded M3 scope and are superseded by the release verification above.

**Latest real candidate acceptance (2026-11-18):** [PR #329 pixel report](https://github.com/pkking/ezwallpaper/pull/329#issuecomment-6985799609) verifies the same `v0.3.0` candidate `36aca9e0` applied at an actual 17:00 UTC user-timer tick, both outputs' getter/state/content SHA matching, unoccluded pixels DP-1 **0.9940** / HDMI-A-1 **0.9991** and unobstructed coverage **0.9676 / 0.9798**; the preregistered matching ≥0.90 and unobstructed ≥0.30 thresholds stayed unchanged. ## M4: complete desktop visual integration

- **G-03 — [#56](https://github.com/pkking/ezwallpaper/issues/56):** a single hour/epoch drives the desktop, lockscreen, SDDM and Plymouth image selections. Each surface requires independently tested real results. The greeter may cache images; changing a pathname is not evidence the live login screen refreshed. Plymouth images packaged inside initramfs apply according to the next-boot boundary; **do not promise hourly boot images or perform hourly initramfs rebuilds** without a separate safe architecture decision.
- **G-04 — [#58](https://github.com/pkking/ezwallpaper/issues/58):** video wallpaper/poster frame pipeline, Noctalia vs mpvpaper renderer ownership and actual lockscreen animations; date/weather and accurate executing-agent counts belong to their respective Noctalia/external provider services, not to the headless wallpaper Core. Never substitute OS process count for real Agent task count.
- **G-06 and lifecycle — [#52](https://github.com/pkking/ezwallpaper/issues/52), [#53](https://github.com/pkking/ezwallpaper/issues/53), [#57](https://github.com/pkking/ezwallpaper/issues/57):** sourcing, derivation, provenance, retention and explicit previewable garbage collection across sessions.
- **Release qualification:** evidence on all *advertised* platforms/surfaces; install/upgrade/rollback and failure recovery. Unsupported surfaces are labeled and must not silently downgrade advertised capabilities.

## Release decision rules

1. **Release proof before labels.** Use `IMPLEMENTED`, `VIRTUAL_VERIFIED`, `PHYSICAL_VERIFIED` and `BLOCKED_EVIDENCE` as defined in [goal-gates.md](docs/agents/goal-gates.md). A tool being merged, a sample CI fixture or green pull request does not authorize a higher proof level.
2. **Beta/no-go:** unresolved released-niri compatibility or missing real mixed-DPI physical and timer evidence blocks M2; do not relabel an experimental virtual success as Beta-ready.
3. **Stable/no-go (satisfied for the published v0.3.0 scope):** #325 L1-L4 layered reliability audit and final-candidate real-hour regression, #326 reproducible install/upgrade/uninstall/rollback, #327 supported dependency recovery/risk-approved exclusions, and final-version provenance are required. Critical image/state loss or unrecoverable wallpaper conflicts block M3. Continuous 24h Soak absence must be disclosed, never treated as physical PASS.
4. **v1/no-go:** incomplete user-visible cross-surface or promised dynamic integration blocks M4. If Plymouth per-hour update is infeasible, document a user-approved scope adjustment instead of falsely closing the Epic.
5. **Agent priority:** finish the highest unmet P0 user gate first; include `Epic`, `Goal`, `Before`, `After`, `Evidence plan` and `Remaining unassessed` in new PRs. After three merged implementation PRs for one gate, reassess the end-to-end proof rather than opening another marginal isolated test.
6. **No phantom releases.** A milestone is published only when GitHub shows its actual Tag/Release, exact commit, package result and prerelease/stable flags. Maintain a changelog and keep open Issues until their entire user acceptance scope passes.

## Where progress is tracked

The [Epic #60](https://github.com/pkking/ezwallpaper/issues/60) owns user objectives; [goal-gates.md](docs/agents/goal-gates.md) records detailed evidence by G-01..G-06; GitHub Issues specify testable deliverables; [AGENTS.md](AGENTS.md) and [workflow.md](docs/agents/workflow.md) enforce the PR/plan/CI workflow; [Releases](https://github.com/pkking/ezwallpaper/releases) are the authoritative version publication record.
